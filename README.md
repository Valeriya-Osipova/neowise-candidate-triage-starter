# Тестовое Neowise. AI-помощник для входящих заявок

Менеджер вводит текст заявки и получает тему и черновик ответа. Он сам читает результат и решает, что писать клиенту. Страница ничего не отправляет клиенту.

Нужен Node.js 20 или новее. Зависимостей и ключей нет, отдельная установка пакетов не требуется.

## Запуск

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт задаётся переменной `PORT`. Ожидание модели по умолчанию — 300 мс, его можно изменить через `TRIAGE_TIMEOUT_MS`.

## Тесты

```sh
node --check server.mjs
node --check triage.mjs
node --check client-state.mjs
node --test
```

В проекте нет отдельного линтера и проверки типов. `node --check` проверяет синтаксис, `node --test` запускает встроенный тестовый раннер.

## Что исправлено

- Пустой текст и текст из пробелов отсекаются на странице и в `POST /api/triage`. В имитатор он не уходит. API отвечает `400` и `{ "status": "invalid_input" }`. Так же обрабатываются отсутствующее поле, нестроковое значение и битый JSON.
- Успешный разбор отвечает `200` и `{ "status": "ready", "topic": "…", "draft": "…" }`. Допустимые темы: `delivery`, `pricing`, `other`. Черновик — непустая строка после удаления пробелов.
- Таймаут, исключение имитатора, не-JSON и неподходящая структура отвечают `200` и `{ "status": "manual_review", "topic": null, "draft": null }`. Ответ `200` от самой модели не считается успешным разбором: неизвестная тема и черновик из пробелов тоже уходят в ручной разбор.
- Страница оставляет исходную заявку, очищает предыдущие тему и черновик и показывает, что заявку нужно обработать вручную. Черновик можно дописать в поле на странице.
- Если ответы приходят не по порядку, на экране остаётся только результат последнего отправленного запроса. Завершение старого запроса не оставляет страницу в состоянии ожидания.

Имитатор `mock-ai.mjs` не менялся. Метки в тексте по-прежнему включают сбои: `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`. Обычный текст разбирается как раньше: «достав» — доставка, «цен» или «стоим» — стоимость, иначе «другое».

## Как проверить сбои

1. Запустите `node server.mjs` и откройте http://127.0.0.1:3000.
2. Отправьте пробелы — появится подсказка, запрос к модели не выполняется.
3. Отправьте «Когда будет доставка?» — появятся тема «Доставка» и черновик.
4. Отправьте текст с одной из меток выше. Предыдущий черновик исчезнет, заявка останется на экране, поле ответа будет пустым и доступным для ручного текста.
5. Автоматических тестов достаточно, чтобы не ждать полную паузу имитатора: таймаут в тестах сокращён до десятков миллисекунд.

## Польза для менеджера

Заявка не теряется, старый черновик не выглядит как ответ на новую заявку, а при сбое можно сразу продолжить вручную. Это можно измерить долей заявок, которые менеджер закрывает без возврата к предыдущему черновику, и числом случаев, когда клиенту едва не ушёл ответ от другой заявки.

## Ограничения

- Имитатор вызывается функцией в том же процессе, а не по сети. Сетевой обрыв и ошибка провайдера одинаково превращаются в исключение и затем в ручной разбор.
- Лимит 300 мс рассчитан на выданный имитатор. Для настоящей модели его нужно задавать отдельно.
- Черновик, который менеджер дописал вручную, хранится только на открытой странице и пропадёт при обновлении.
- Повторное нажатие «Разобрать заявку» заменяет текущий черновик результатом нового запроса.
